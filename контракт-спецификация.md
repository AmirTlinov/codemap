# Flagship-контракт codemap

## Владелец и состояние

Этот документ владеет одним вопросом: когда `codemap` можно публично назвать
flagship-инструментом для coding agents.

Стабильной CLI-формой владеет [`docs/PRODUCT.md`](docs/PRODUCT.md), устройством
реализации — [`docs/IMPLEMENTATION.md`](docs/IMPLEMENTATION.md), наблюдаемыми
границами — [`docs/CURRENT_LIMITATIONS.md`](docs/CURRENT_LIMITATIONS.md), а
парным измерением — [`docs/BENCHMARK_AB.md`](docs/BENCHMARK_AB.md).

Исходная identity `v1.0.0` является **candidate**, пока нет принятого
эксперимента и GitHub Release с той же проверяемой сборкой. После
публикации этой release identity её статус определяет не маркер в файле, а
опубликованный immutable evidence bundle и его acceptance receipt.

### Измеренное состояние

Первая незагрязнённая попытка для commit `5d857a1` и binary
`deee6efba5d86fdb5319e2cede47ffbd7c9008db6eec5ea587e4a3824865fb89`
завершила все 72 run: 36/36 пар валидны, read-only задачи не
изменили репозитории, exact controls не регрессировали. Treatment
поднял среднюю completeness с 73,4% до 77,1% и required pass-rate с
55,6% до 63,9% при 7,2% time overhead и −4,3% input-token overhead на
сложных задачах.

Попытка **не принята**: 7/12 complex wins вместо 8, четыре
task loss и три потери required criterion. Каждая потеря возникла
только в одном из двух повторов; парные истории не доказали
отсутствия или искажения структурного факта картой. Поэтому
этот результат не оправдывает ни релиз, ни подгонку codemap под
единичные решения модели. Candidate остаётся не flagship. Эта попытка
остаётся оценённой по своему заранее замороженному двухповторному контракту:
новая семантика устойчивого эффекта не применяется к ней ретроактивно.

## Обещание

`codemap` — детерминированная read-only карта внимания. Она даёт агенту
наблюдаемых владельцев поведения, связи и границы, но не решает за него,
как исследовать, что менять и чем доказывать результат.

Продукт считается доказанно эффективным, когда одинаковый агент на одинаковых
реальных задачах с `codemap` получает более полный машинно проверяемый результат,
не проигрывает control ни на одной сложной задаче и сохраняет ограниченную цену.

Compression, количество найденных путей и красивый финальный отчёт сами по себе
не являются доказательством эффективности. Результат доказывает внешний verifier;
парный разбор полной истории объясняет, как карта изменила внимание агента.

## Неизменные свойства продукта

- один project-agnostic binary;
- ноль записей в target repository по умолчанию;
- внешний cache по умолчанию;
- exact и scoped входы сохраняют уже известный anchor без принудительного root dump;
- root atlas ограничен текущим уровнем и не выдаёт весь репозиторий;
- observed facts имеют происхождение;
- hidden, unsupported и dynamic границы видимы;
- нулевая находка отличима от неполного наблюдения;
- `proof` показывает verification surfaces, а не выносит verdict;
- никакого task router, ranking engine, embeddings или LLM в hard path;
- project commands исполняются только через явный `proof --run`.

## Основные входы

Когда структурная карта полезна, доступны соразмерные входы:

```bash
codemap where <symbol>
codemap cone <file-or-file#symbol>
codemap ls <file-or-directory>
```

`codemap ls .` даёт current-level orientation. `Expand` и пост-изменительные карты также
являются возможностями, а не обязательным распорядком:

```bash
codemap changed
codemap proof changed
```

## Доказательство эффективности

### Сравнение

Владелец — существующий `scripts/benchmark-codemap-ab.py`. Обёртка
`scripts/benchmark-codemap-flagship.py` только замораживает вход, запускает пары и
выпускает evidence. Один сравнительный агент реконструирует причинную разницу двух
траекторий; scoring service, голосования, судей над судьями и adjudication нет.

Обе руки получают один commit, prompt, модель, reasoning, permissions, timeout
и внешний verifier. Единственное плановое различие: treatment имеет доступ к `codemap`,
control — нет. Подсказка treatment только называет основные read-only входы: она не
задаёт порядок вызовов, обязательные Expand или verification path.

Corpus содержит шесть несвязанных репозиториев и четыре ecosystem families. На
каждом репозитории есть:

1. deterministic investigation с заранее замороженными source-backed claims;
2. multi-file implementation с hidden external test или contract check;
3. exact/local control, где карта не должна добавлять ритуал.

Investigation получает одну настоящую runtime/file/symbol точку входа и вопрос о
поведении. Prompt не перечисляет ожидаемых владельцев, proof-файлы или словарь
искомой цепи: их должен обнаружить агент, а проверяет только внешний verifier.

Итого: 18 задач, четыре counterbalanced повтора, 144 agent runs. Для каждой
задачи каждая рука запускается ровно дважды первой и дважды второй.

### Истина результата

Каждый criterion имеет внешний исполнимый verifier. Investigation проходит criterion,
когда отчёт ссылается на каждого заранее замороженного evidence-owner реальными
`path:line`-ссылками, а его source bytes всё ещё содержат замороженные причинные
якоря. Конкретная формулировка отчёта, каталог открытых файлов и повторение путей
не являются outcome.
Implementation проверяется независимыми hidden behavior groups и contract/regression checks,
чтобы частичный результат давал детерминированную полноту, а не один монолитный pass bit. Exact control
проверяет outcome и изменённые bytes.

У investigation есть минимальное required causal core и отдельные claims полноты:
основная цепь определяет, выполнена ли задача, а найденные proof boundaries, реальные
ограничения и дополнительные переходы увеличивают deterministic completeness.

Длину и стиль ответа, model self-report и мнение анализатора о качестве результата
gate не используют. Невыгодная пара не исключается post-hoc.
Агент недетерминирован: он может получить нужную информацию и не использовать её.
Такой run остаётся валидным и участвует в outcome; он не превращается в дефект
карты без доказанного пропуска, искажения или шума в самом codemap-выводе. Отклонение
от подсказанной последовательности команд также не аннулирует run; невалидным является
только заражение control доступом к codemap.

Для каждой пары сохраняются полные события, команды и чтения, codemap-выводы, diff,
verifier outputs, время и tokens. Сравнительный агент получает их как Arm A и Arm B
и со ссылками на конкретные события отвечает: как строилось понимание, когда найден
владелец, какие связи были замечены или пропущены, что повлияло на правку, где карта
сократила поиск или добавила шум и подтверждается ли вывод diff и verifier.

Этот разбор не меняет completeness, wins или thresholds. Внешний verifier отвечает
«задача выполнена?», а парная история — «как codemap изменил внимание и почему
результат стал лучше, хуже или остался тем же?». Полная история остаётся фактом
эксперимента и основанием причинного разбора, а не вторым субъективным score.

### Принятие

Результат принимается только одновременно по трём условиям:

1. из 12 сложных задач treatment устойчиво выигрывает минимум 8 и устойчиво
   не проигрывает ни одну: win означает лучшую deterministic completeness минимум
   в трёх из четырёх повторов, loss — худшую минимум в трёх из четырёх, остальные
   направления нейтральны;
2. обязательный criterion считается потерянным только когда control проходит его,
   а treatment нет минимум в трёх из четырёх валидных пар; exact regression
   определяется тем же устойчивым направлением парных task outcomes;
3. медианный complex overhead не превышает 20% wall time и 15% input tokens,
   а медианный exact-control overhead не превышает 10% по обеим метрикам.

Средняя completeness delta всех четырёх повторов сохраняется и публикуется как
величина эффекта, но не определяет его направление. Один стохастический промах и
даже два неустойчивых разнонаправленных результата не делают task loss, required
regression или exact regression.

Пара считается валидной, когда обе руки завершились, сохранили ожидаемые commit,
prompt/model/binary identities и не изменили запрещённые paths. Инфраструктурный
сбой автоматически повторяется один раз с тем же manifest. Повторный сбой делает
gate красным; denominator не уменьшается.

Treatment-preflight не является outcome-gate и не требует `18/18`: он проверяет, что corpus,
запуски карты и внешние verifier-ы технически исполнимы. Его outcome-промахи — диагностика,
а не основание подгонять codemap под один случайный выбор модели.

Если gate не проходит, пороги не меняются. Исправляется существующий владелец
поведения, собирается новая binary identity, и весь corpus выполняется заново.
Неуспешная попытка остаётся в evidence bundle.

### Evidence bundle

Один immutable bundle содержит:

- corpus и task manifests с hashes;
- repo commits, prompts, model/reasoning и pair order;
- exact `codemap` binary identity и SHA-256;
- raw результаты обеих рук и verifier outputs;
- полные парные истории действий, diff и причинный разбор со ссылками на события;
- completeness, time и input-token deltas по каждой задаче;
- короткие JSON и Markdown summaries;
- hashes всех входов и результатов.

## Release boundary

Версия может называться flagship только когда:

1. её exact binary прошёл эксперимент выше;
2. local и remote gates зелёные на macOS, Linux и Windows;
3. checksummed и attested artifacts скачаны обратно и исполнились на каждой
   поддержанной платформе;
4. чистый mixed monorepo прошёл `ls .` → exact anchor → change → `changed` →
   `proof changed` → JSON scenario без записей `codemap` в repository;
5. README и release notes называют только измеренный эффект и дают ссылку на
   evidence bundle.

Публичный flagship release — `v1.0.0`. Registry — GitHub Releases; Homebrew
formula использует тот же immutable macOS archive и checksum. До выполнения
этих условий допустимы candidate и maintenance builds без flagship-утверждения.

## Известная граница

Статическая карта не видит произвольные reflection, dependency injection,
computed strings, внешние runtime-состояния и все межъязыковые subprocess связи.
Она обязана показывать такой край как typed horizon. Flagship не означает, что
карта знает всё; он означает, что видимая и ограниченная структурная правда
наблюдаемо помогает агенту завершать реальные задачи полнее.

## Конечная форма

Flagship — не статус разработки и не суд над процессом. Это воспроизводимый
факт о продукте:

> На опубликованном корпусе реальных задач агент с конкретной released binary
> `codemap` достигает более полного внешне проверенного результата без регрессий
> и в заявленной границе стоимости.
