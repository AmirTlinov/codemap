# main_cluster: аналитический A/B с codemap и без него

Срез на 2026-07-14. Этот эксперимент проверяет не скорость локальной правки, а
главное продуктовое обещание codemap: помогает ли структурная карта агенту
понять больше существенных связей в крупном связном репозитории.

## Постановка

Два изолированных `codex exec` получили:

- модель `gpt-5.6-sol` с reasoning effort `xhigh`;
- один чистый commit `main_cluster@0a502f91ca04`;
- один и тот же запрос на 8–12 доказательных системных проблем;
- требование покрыть приложения, shared packages, CI/release, deployment,
  данные/контракты и operational docs;
- требование дать `path:line`, причинную цепочку, потребителей, failure mode и
  существующую или отсутствующую проверку;
- запрет сети, Linear, памяти, live-инфраструктуры и любых правок репозитория.

Control использовал обычные read-only инструменты, а вызов `codemap` был
заблокирован. Treatment начал с `codemap ls .`, затем использовал causal graph,
карту workflows, `cone` для `release-prod.yml`, runtime-карту Control Center и
contract-карту outbox migration.

Оба запуска были валидны и не изменили ни одного файла.

Простая формальная проверка доказательности дала обоим отчётам 100%: оба были
длинными, многослойными и хорошо подкреплёнными. Поэтому содержательное отличие
оценивалось двумя дополнительными слепыми проходами `gpt-5.6-sol/xhigh`.
Порядок отчётов был обратным во втором проходе, а признаки treatment/control из
текстов были удалены.

## Что увидели оба агента

Оба отчёта обнаружили две важные системные границы:

- автоматический CI способен завершиться успешно для application-изменений без
  запуска полноценных application gates;
- workflow с именем Tenant Registry GitOps способен применить весь production
  overlay, обходя более узкое обещание владельца.

Control особенно глубоко разобрал release/runtime-операции: отсутствие
failure-atomic rollback, неработающий deployment freeze, всегда успешный HTTP
health, несовместимые tenant DB env-контракты, самостоятельно выпущенный JWT в
release smoke, secret rotation и неограниченные migration locks.

## Что дополнительно раскрыл агент с codemap

Слепые судьи выделили несколько тяжёлых цепочек, отсутствовавших в control:

1. Анонимные `/api/agent/panels` принимают произвольный `tenantId` и допускают
   межтенантное чтение и изменение без session, capability, CSRF и tenant grant.
2. Production manifest явно отключает Origin/Referer CSRF enforcement, хотя код,
   тесты и документация ожидают включённую защиту.
3. Panel-конфигурация при текущем deployment остаётся process-local, а даже при
   Redis имеет TTL один час: UI сообщает успех, но состояние исчезает.
4. Outbox secret существует в overlay, но не попадает в Deployment; env-контракт
   не совпадает с adapter, события уходят в неограниченный memory buffer, health
   остаётся успешным, а domain write и outbox INSERT не образуют одну транзакцию.
5. OpenAPI source и runtime имеют product-detail route, но generated client его
   потерял, а generation-diff gate отсутствует.
6. Tenant Registry GitOps расшифровывает production Secrets и загружает полный
   plaintext render как Actions artifact.

Судьи сочли решающим не количество ссылок, а более цельное восстановление
скрытых security-, durability- и contract-цепочек через приложение, shared
package, deployment и verification rails.

## Интерпретация

На этой сложной аналитической задаче codemap дал **небольшое, но согласованно
подтверждённое улучшение контекстного понимания**: `+2,5/100` при `+7,3%` input
tokens и `+15,2%` времени.

Это противоположно простому однофайловому smoke, где патчи были одинаковыми, а
codemap добавил только стоимость. Текущая картина поэтому зависит от формы
задачи:

- известная локальная точка без значимых связей — карта не окупилась;
- крупный незнакомый связный репозиторий и поиск скрытых проблем — карта помогла
  заметить более глубокие межвладельческие цепочки.

## Граница утверждения

Это одна пара, один репозиторий, один открытый аналитический запрос и одна модель.
Судьи используют ту же модель, поэтому не являются полностью независимым
человеческим ground truth. Результат является первым положительным
task-specific evidence, но ещё не общим доказательством lift. Для общего вывода
нужны другие крупные репозитории, несколько аналитических задач и повторения.

Полные локальные артефакты находятся в
`target/codemap-ab/main-cluster-analysis-20260714/`: исходные ответы, события,
usage, verifier-метрики, переставленные judge prompts, два judge verdict и
сводный `evaluation.json`.
