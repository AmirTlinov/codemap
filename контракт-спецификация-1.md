# Контракт-спецификация 1 — codemap как прогрессивная лупа внимания агента

Дата: 2026-07-14. Основание: полный аудит кода, тестов и живой прогон v0.2.36.

Роли документов: `docs/PRODUCT.md` владеет продуктовыми инвариантами, `docs/IMPLEMENTATION.md` — картой модулей. Этот документ владеет **путём дореализации до флагманского состояния**: последовательностью вертикальных слайсов, каждый из которых самостоятельно доводится до зелёных тестов, обновлённых доков и version bump. Когда слайс закрыт, его инварианты переезжают в `PRODUCT.md`/тесты и становятся постоянным контрактом.

---

## 1. Кристаллизованное намерение

**codemap — прогрессивная лупа внимания агента.** Не судья, не советчик, не энциклопедия — карта того, что реально есть, с ручкой увеличения.

Три закона, разрешающие главное противоречие («полнота внимания» против «не заваливать»):

1. **Полнота по ширине.** На текущем уровне увеличения кадр перечисляет *все категории* существующего — хотя бы счётчиком. Агент всегда знает, чего он не видит. Слепота молчит о скрытом; энциклопедия вываливает всё; лупа показывает счёт и даёт ручку.
2. **Экономия по глубине.** Перечисления ограничены бюджетом. Каждая скрытая группа посчитана и имеет ровно одну точную команду углубления. Глубже — только по явному запросу агента.
3. **Правда без вердикта.** Карта утверждает только доказуемое, с происхождением (provenance) и координатами. Незнание — типизированный факт первого класса. Выводы, оценки и рекомендации остаются за агентом.

Флагманское состояние: инструмент, который любому агенту в любом репозитории даёт честный уровень зрения (пусть минимальный — инвентарь и git-правда), никогда не врёт уверенной цифрой, окупает каждый токен вывода и доставляется агенту без человека-посредника.

## 2. Аксиомы карты (K1–K10)

Поведенческий контракт. Каждый слайс ссылается на аксиомы, которые реализует; нарушение аксиомы в любом выводе — баг.

- **K1. Провенанс у каждого факта.** Всякое утверждение карты помечено источником (`hard`/`soft`/typed unknown) и, где применимо, точным `file:line`.
- **K2. Честный ноль.** Счётчик показывает `0` только когда ноль доказан (область просканирована, поток поддержан). Иначе — `unknown (<typed reason>)`. Ложный уверенный ноль — худший обман карты: он выключает внимание агента.
- **K3. Не суд.** Словарь вывода — только факты: found, linked, missing, soft match, unknown, счётчики, координаты, существование runnable-поверхностей. Запрещены вердикты и рекомендации (словарь — Приложение A). Expand-команда — не совет действия, а продолжение взгляда.
- **K4. Полнота по ширине кадра.** Кадр обязан упомянуть каждую категорию, существующую на уровне, минимум счётчиком в `Hidden`. Молча выброшенных категорий не бывает.
- **K5. Ровно одна ручка на скрытое.** Каждая скрытая группа имеет один счётчик и одну Expand-команду. Два счётчика одного понятия — баг.
- **K6. Один факт — один раз.** Одно ребро/поверхность в одной роли перечисляется в кадре один раз. Другие секции ссылаются счётчиком, не повтором списка.
- **K7. Каждый Expand исполняем.** Любая напечатанная командой карты команда синтаксически валидна, завершается успешно и показывает обещанное. Это исполняемый тест, не пожелание.
- **K8. Детерминизм и нулевой след.** Без сети, без LLM, без записи в целевой репозиторий (кроме явного `init`). Одинаковый вход → одинаковая карта.
- **K9. Fail-honest.** Не смогли распарсить/разрешить — typed unknown, не guessed edge и не падение. Битая конфигурация — fail-closed для карт (как сейчас).
- **K10. Токеновый потолок — исполняемый контракт.** У каждой линзы объявленный бюджет по умолчанию, закреплённый тестом. Превышение — красный тест, не «жалко, но ладно».

## 3. Протокол лупы

Уровни увеличения — конечны и явны:

```txt
L0  codemap ls .                    домен/пакеты/скрипты/границы репозитория
L1  codemap ls <scope>              один уровень: файлы, символы, входящие
    codemap cone <anchor> --depth 1 кадр вокруг одного якоря
L2  --all / --limit N / фокус-линзы (runtime, contract, flow, impact, …)
L3  чтение исходника самим агентом  карта доводит до точного file:line
```

Каждый вывод заканчивается навигационными ручками следующего уровня. Карта никогда не читает исходник за агента на L3 — она даёт координаты.

**Бюджеты по умолчанию** (не-brief, закрепляются расширением `tests/line_budget.rs`; токены ≈ `ceil(chars/4)`, формула фиксируется в тесте):

| Линза | Строк ≤ | ~Токенов ≤ |
| --- | --- | --- |
| `ls .` | 120 | 1500 |
| `cone <file> --depth 1` | 90 | 1100 |
| `changed` (≤150 файлов) | 130 | 2000 |
| `proof changed` | 90 | 1200 |
| `where` (одно определение) | 60 | 700 |

## 4. Зафиксированное исходное состояние (аудит 2026-07-14)

Что работает: сборка 23 с; `fmt`/`clippy` чистые; **600/600 тестов** за ~80 с; тёплые запуски 0.2–0.4 с; токен-дисциплина соблюдается (`changed` на 114 грязных файлах — ~1.7K токенов); факты точны на чужом TS-репо (включая разрешение циклического импорта `".."`); честные Unknown/Not Found.

Зафиксированные дефекты (входы слайсов):

1. **Ложный ноль**: `where ConeReport` → `consumers: 0` при реальных ≥9 файлах-потребителях; причина — `include!()`-поток не распознан; `unsupported_symbol_flow` в Unknown не спасает уверенную цифру. (K2)
2. **Дубли кадра cone ~30–40% токенов**: Inputs ≡ Links→outgoing; Verification Sensors ≡ Soft Surface Matches; hidden двумя счётчиками («hidden: 8» и «hidden by limit: 38»). (K5, K6)
3. **Мелкая неправда**: `LANG_SUPPORT.md` классифицирован как `adapter`; `fixtures/**/package.json` в «repo-local guard files»; `proof_runner`/`proof_rail` — дубль-группы; поле `path:` содержит `test: cargo test`; у ребра из `".."`-импорта нет `line`. (K1, K2)
4. **Хрупкий граф**: самописные сканеры — вложенные template strings ломают JS-сканер (`src/repo/js_scanner.rs`), regex-литералы эвристикой, Python namespace/poetry-пути не поддержаны, Rust `include!` не ребро. Уникальная ценность карты (рёбра) — наименее надёжная её часть. (K1, K9)
5. **Ценность не измерена**: `scripts/benchmark-codemap-ab.py` (1280 строк) ни разу не прогнан; нет ни `tasks.jsonl`, ни артефактов.
6. **Холодная скорость**: `changed` холодный — 7.7 с (114 файлов); `src/evidence.rs:27` перечитывает уже отсканированные файлы ради номеров строк; `changed` делает три независимых прохода графа.
7. **Универсальность не выражена**: нет заявленного уровня зрения для неподдержанных языков; ноль Windows-тестов; non-UTF8 не тестирован; stress-кейсов нет.
8. **Доставка**: канал до агента — человек вручную; MCP нет; `init --agents` существует, но не флагманский сценарий.
9. **Дистрибуция**: имя `codemap` на crates.io занято чужим крейтом (4M загрузок); установка только `--path`; последний релиз v0.2.33 (2026-05-04).
10. **Внутреннее**: `include!`-монолит (78 включений в `map.rs`, один namespace на 16.6K строк); файлы нарезаны механически под лимит ~500 строк; `changed_*` ×8 файлов с копипастой `push_changed_risk`; протечки слоёв (`src/map/boundary.rs:56-217` печатает текст, `changed_receipt_events.rs` парсит JSON в map).

## 5. Слайсы

Каждый слайс — вертикальный: model → map → render → schema → тесты → доки → version bump. Слайс закрыт, когда приёмка зелёная **на фикстурах и на самом codemap**.

---

### Слайс 1 — «Карта не утверждает недоказанного»: честный ноль и мелкая правда

**Аксиомы**: K1, K2. **Размер**: малый. **Это фундамент доверия — первым.**

**Мотив.** `consumers: 0` при реальных 9 потребителях — сигнал «меняй смело» от инструмента, проданного как защита от слепых правок. Плюс россыпь мелких ложных утверждений (п. 3 исходного состояния), каждое из которых портит именно правду карты.

**Станет.**
- Каждый счётчик потребителей/входящих/verification-рёбер несёт провенанс из трёх состояний: `counted(n)` (перечислением), `proven-zero` (область просканирована, поток поддержан), `unknown(<reason>)` (поток не поддержан / вне охвата). Владелец типа — `src/model`.
- Рендер: `consumers: unknown (rust include! flow)` вместо `consumers: 0`; в JSON счётчик — объект со статусом (schema bump `schemas/manifest.json`).
- Точки классификации: символ в файле, участвующем в неподдержанном потоке (`include!`, dynamic import, реэкспорт вне охвата) → unknown, не ноль. Затрагивает `where`, `cone` X-Ray Card, `contract`, `impact`.
- Мелкая правда: `.md` не может получить роль `adapter`; `fixtures/**` исключены из guard-files; `proof_runner`/`proof_rail` слиты или различены содержательно; поле `path:` содержит путь; отсутствие `line` у ребра — явный `line=unknown`, не молчание.

**Приёмка.**
- На самом codemap: `where ConeReport` и `cone src/model/lens_reports.rs` не печатают `consumers: 0`; печатают `unknown (…)`.
- Новая фикстура: Rust-репо с `include!`; JS-репо с dynamic import — оба дают `unknown`, не `0`.
- Негативный тест: доказанный ноль остаётся `0` (изолированный файл без потребителей в полностью поддержанном TS-репо). **Граница: не размыть всё в unknown — тотальный unknown такой же обман, как ложный ноль.**
- Тесты мелкой правды: markdown-роль, guard-фильтр, дубль-группы.

**Не делаем**: не чиним само разрешение `include!`/dynamic import (это слайс 5) — только перестаём врать.

### Слайс 2 — «Один факт — один раз»: кадр cone без повторов

**Аксиомы**: K5, K6, K10. **Размер**: малый-средний.

**Мотив.** 30–40% токенов флагманской команды — повтор: импорты дважды (Card→Inputs и Links→outgoing), сенсоры дважды, скрытое двумя счётчиками. Для продукта, чья метрика — сигнал на токен, это потеря на самом видном месте.

**Станет.** Спецификация кадра cone (закрепляется тестом структуры):

```txt
X-Ray Card    роль, агрегаты (counts) — без перечисления путей
Edges         единственное место перечисления рёбер: outgoing / incoming / verification
Contracts     контрактные поверхности
Unknown       типизированные пробелы
Hidden        один счётчик на секцию + одна Expand-команда  (K5)
```

Card показывает агрегаты и указывает на Edges; каждый путь в одной роли встречается в тексте один раз. Hidden-бухгалтерия сводится к одному счётчику на секцию.

**Работы**: `src/map/cone_xray.rs`, `src/render/cone_xray.rs`, обновление затронутых текстовых тестов.

**Приёмка.**
- На эталонных фикстурах и на `cone src/map.rs --depth 1` самого codemap: токены ↓ ≥25%, при этом **множество уникальных фактов до = после** (JSON-сравнение).
- Инвариант-тест: ни одно ребро `(from, to, kind)` не перечислено дважды в текстовом кадре.
- Один `hidden`-счётчик на секцию; бюджет cone из §3 закреплён в `tests/line_budget.rs`.

### Слайс 3 — «Исполняемая лупа»: единый Hidden/Expand-протокол с самопроверкой

**Аксиомы**: K4, K5, K7. **Размер**: средний.

**Мотив.** Механика Expand есть, но неоднородна между линзами; никто не гарантирует, что напечатанная команда валидна. Лупа, у которой ручка прокручивается вхолостую, теряет доверие мгновенно.

**Станет.**
- Инвентаризация всех линз (`ls`, `cone`, `changed`, `proof`, `proof-map`, `runtime`, `contract`, `impact`, `diff-map`, `flow`, `siblings`, `place`, `delete`, `boundary-map`, `where`, `graph`): каждая скрытая группа — один счётчик + одна Expand-команда; ни одного hidden без ручки, ни одной ручки без счётчика.
- **Самопроверяющий harness** (расширение `tests/structural_map/dogfood_harness.rs`): на фикстурах и на самом codemap собрать все `expand:`-строки из всех линз, исполнить каждую, assert: exit 0, непустой stdout, без паник, и вывод раскрывает ≥ заявленного скрытого.
- В `schemas/manifest.json` Expand-команда — обязательное поле скрытой группы.

**Приёмка**: harness зелёный на фикстурах и на codemap; schema-тест обязательности; K4-тест — категория, существующая в фикстуре, но выброшенная из кадра без счётчика, валит тест.

### Слайс 4 — «Измеренная ценность»: первый прогон A/B (развилка)

**Аксиомы**: правда о себе. **Размер**: операционный, не кодовый. **Запускается после слайса 3, может идти параллельно слайсу 5.**

**Мотив.** Единственная причина существования продукта — «агент с картой работает лучше» — не проверена собственным, уже написанным инструментом. Слайсы 1–3 обязаны пройти раньше: ложный ноль и дубли токенов портят именно treatment-arm.

**Работы.**
- Составить `tasks.jsonl`: 10–15 задач на 2–3 внешних репозиториях (не codemap), оба режима (`implementation`, `analysis`), weighted external completeness criteria по формату `docs/BENCHMARK_AB.md`.
- Прогнать ≥3 репетиции; зафиксировать SHA репозиториев, модель, effort, версию codemap.
- Артефакты → `docs/benchmarks/<дата>/`; итог → `docs/BENCHMARK_RESULTS.md` с claim boundary: что доказано, что нет.
- **Публиковать и негативный результат.** Карта правды начинается с правды о себе.

**Приёмка**: результаты воспроизводимы из закоммиченной конфигурации; README «Measure The Win» ссылается на реальные числа.

**Развилка**: если treatment не выигрывает — остановка, разбор *где именно* карта не помогла (какие линзы вызывались, что агент делал вместо), пересмотр приоритетов слайсов 5–8 по данным, а не по интуиции.

### Слайс 5 — «Правдивый граф»: точность рёбер там, где живёт уникальная ценность

**Аксиомы**: K1, K9. **Размер**: крупный. **Самый большой рычаг качества фактов.**

**Мотив.** Инвентарь и git-правду агент добудет и сам; уникальная ценность codemap — рёбра (потребители, verification links). Именно они построены на самописных regex-сканерах и хрупки. Детерминированный парсер не нарушает инвариант «no LLM in the hard path».

**Порядок внутри слайса** (каждый шаг — самостоятельный под-слайс с приёмкой):

- **5.1 Rust `include!` — ребро.** Распознавать `include!("path")` как import-ребро в rust-сканере. Само-карта codemap становится правдой: consumers из `unknown` → `counted`. Приёмка: `where ConeReport` на codemap показывает counted ≥ 9; фикстура include!-репо.
- **5.2 tree-sitter для JS/TS** за существующим интерфейсом извлечения в `src/repo/*`; regex-сканеры остаются для прочих языков. Adversarial-корпус фикстур: вложенные template strings, regex-литералы рядом с делением, JSDoc, `import()` → typed unknown. Приёмка: корпус зелёный; все существующие тесты зелёные.
- **5.3 Python-пути**: namespace packages, poetry `[tool.poetry.packages]`, src-layout расширенно (tree-sitter-python — по результатам 5.2).

**Бюджеты слайса**: холодный `ls .` на среднем репо не медленнее +20%; бинарь не тяжелее +10 МБ; замер закрепляется в CI.

**Не делаем**: новые языки (Kotlin/Java/C#…) — давление «поддержать всё» снимает tier-модель слайса 6.

### Слайс 6 — «Любой проект»: уровни зрения и честная деградация

**Аксиомы**: K2, K4, K9. **Размер**: средний.

**Мотив.** «Нужен любому агенту в любом проекте» ≠ «парсим все языки». = «в любом репозитории карта честно объявляет доступный уровень зрения и не деградирует молча». Сегодня деградация молчаливая, Windows не покрыт, non-UTF8 не тестирован.

**Станет.**
- **Tier-модель зрения**, объявляемая в `doctor` и корневом `ls .` одной строкой:

```txt
T0  инвентарь + git-правда + changed        (любой репозиторий)
T1  + пакеты / скрипты / тестовые поверхности
T2  + граф импортов и потребителей
T3  + runtime / contract / flow
```

  Пример: `vision: T2 (ts, python) · T0 (haskell — edges unknown)`. Это K2 на уровне репозитория: агент знает, каким глазом смотрит.
- Все линзы при неподдержанном языке выдают typed unknown, не пустоту.
- non-UTF8/бинарные файлы: skip + счётчик в Hidden (`undecodable`), никогда паника.
- Windows: job в CI-матрице (`windows-latest`), аудит разделителей путей, кэш в `%LOCALAPPDATA%`.
- Stress-бюджет: синтетический репо ~100k файлов; целевые время/память фиксируются по первому замеру (nightly CI).

**Приёмка**: фикстура «репо на неподдержанном языке» — карта полезна (T0/T1) и объявляет tier; non-UTF8-фикстура; windows-job зелёный; stress-тест с зафиксированным бюджетом.

### Слайс 7 — «Мгновенная лупа»: холодная скорость

**Аксиомы**: K10 (бюджет — это и латентность). **Размер**: малый-средний.

**Мотив.** Тёплые 0.2–0.4 с — отлично; холодный `changed` 7.7 с ломает ритм цикла агента. Известные причины: `src/evidence.rs:27` перечитывает уже отсканированные файлы ради номеров строк на каждое ребро; `changed` собирает diff-map, impact и proof-map тремя независимыми проходами.

**Станет.**
- Номера строк импортов вычисляются один раз при скане и живут в инвентаре (`FileInfo.import_locations`); evidence не открывает файлы повторно.
- `changed` — один проход графа с тремя проекциями.
- `doctor` показывает счётчик открытий файлов за прогон — метрика становится наблюдаемой.

**Приёмка**: холодный `changed` на самом codemap (≥100 грязных файлов) ≤ 3 с (медиана из 3, эталон — dev-машина, метод фиксируется в доке); `doctor`: повторных чтений — 0; тёплые времена не деградировали.

---

### Слайс 8 — «Карта сама приходит к агенту»: доставка

**Аксиомы**: K3, K8 (доставка не добавляет интерпретаций). **Размер**: средний. **Не зависит от 5–7, можно параллельно.**

**Мотив.** Продукт для агентов доставляется через человека, вручную вписывающего команды в промпт. Канал доставки — половина продукта.

**Станет.**
- **8.1 Онбординг-сниппет.** `codemap init --agents` пишет в AGENTS.md эталонный сниппет протокола лупы — ≤ 12 строк, не энциклопедия:

```md
## codemap — карта репозитория
Перед правками: `codemap ls .`, затем `codemap cone <file> --depth 1`.
После правок: `codemap changed`, затем `codemap proof changed`.
Глубже — только командами из строк `expand:` в выводе.
Карта показывает факты и unknown; выводы делаешь ты.
```

  README ведёт с этого сценария как с главного.
- **8.2 MCP.** `codemap mcp` — stdio-сервер в том же бинаре (инвариант «один бинарь в PATH» сохранён). Инструменты 1:1 к линзам (`map_ls`, `map_cone`, `map_changed`, `map_proof`, `map_where`), возвращают тот же читаемый текст + json-поле. Никаких новых семантик, те же бюджеты.
- **8.3 Рецепты**: `docs/AGENTS_INTEGRATION.md` — Claude Code (skill + hooks), Codex, Cursor.

**Приёмка**: MCP handshake-тест + каждый инструмент возвращает байт-в-байт текст CLI-эквивалента (diff-тест); сниппет-тест длины и содержания; задокументированная ручная проверка: свежий агент в фикстуре с одним сниппетом использует codemap без напоминания.

### Слайс 9 — «Имя и дистрибуция»

**Размер**: малый кодом, важный решением. **Не зависит от 5–8.**

**Мотив.** `cargo install codemap` ставит чужой крейт. Установка только из клона. Продвижение до решения имени — расход впустую.

**Станет.**
- Публикация как крейт **`codemap-cli`** с `[[bin]] name = "codemap"` — командное имя сохраняется. (Альтернатива — полное переименование; решение зафиксировать здесь до продвижения.)
- Для публикации подрезать `include` в `Cargo.toml` (fixtures/tests раздувают пакет за лимиты crates.io).
- Release-workflow: бинарники macOS arm64/x64, Linux x64 (musl), Windows x64; метаданные `cargo-binstall`.
- README-инсталляция без клона.

**Приёмка**: с чистой машины `cargo install codemap-cli` (и/или `cargo binstall`) даёт рабочий `codemap --version`; релиз собирает три платформы; страница crates.io живая.

### Слайс 10 — «Внутренние опоры»: модули, дедупликация, слои

**Аксиомы**: внутренний инвариант слоёв repo → map → render. **Размер**: крупный, фоновый. **Ведётся после слайса 3 отдельными коммитами, никогда не смешивается с продуктовыми слайсами.**

**Мотив.** `include!`-монолит (78 включений, один namespace на 16.6K строк) лишает компилятор и IDE возможности помогать, а команду — границ видимости; файлы нарезаны механически под ~500 строк вместо смысла; `changed_*` ×8 с копипастой; render-текст рождается в map (`src/map/boundary.rs:56-217`), JSON парсится в map (`changed_receipt_events.rs`). Это не горит, но облагает налогом каждый будущий слайс.

**Станет.**
- Поэтапная миграция `include!` → настоящие модули: сперва `map/lenses`, затем `repo`, затем `render`. Модульное дерево делает направление слоёв compile-time фактом: map не может импортировать render.
- Политика «≤500 строк на файл» заменяется политикой семантического владения (один владелец поведения — один модуль).
- `changed_*`: таблица `RiskRule { name, severity, predicate }` вместо восьми копий `push_changed_risk`.
- Текстообразование уходит из map в render; парсинг — из map в repo/scan.

**Приёмка**: в `src/` нет `include!` (или только явно задокументированные); `clippy` чистый; слой-инвариант закреплён структурой модулей; поведение — байт-в-байт (существующие 600 тестов зелёные без правок ассертов, кроме заведомо форматных).

## 6. Порядок, зависимости, параллельность

```txt
1 → 2 → 3 ──→ 4 (A/B, развилка: результаты корректируют приоритеты 5–8)
              ├─→ 5 → 6 → 7        (правда графа → универсальность → скорость)
              ├─→ 8                 (доставка — независима от 5–7)
              └─→ 9                 (дистрибуция — независима от 5–8)
10 — фоном после 3, отдельными коммитами
```

Жёсткая последовательность только 1→2→3→4: доверие и кадр обязаны быть чистыми до измерения ценности. Дальше — по ёмкости, но релизная коммуникация (продвижение) не раньше 9.

## 7. Definition of Done контракта в целом

Контракт закрыт, когда всё нижеследующее — зелёные тесты или закоммиченные артефакты:

1. На самом codemap нет ни одного ложного нуля; `where`/`cone` для собственных типов показывают counted-потребителей (после 5.1).
2. Все бюджеты §3 закреплены тестами; кадр cone без повторов фактов.
3. Каждая напечатанная Expand-команда исполняема (harness зелёный на фикстурах и на codemap).
4. `doctor`/`ls .` объявляют tier зрения; неподдержанный язык даёт typed unknown, не молчание; Windows-job зелёный.
5. Холодный `changed` на codemap ≤ 3 с; повторных чтений файлов — 0.
6. `docs/BENCHMARK_RESULTS.md` с воспроизводимым A/B-прогоном опубликован (любой исход).
7. Установка с чистой машины одной командой; релизные бинарники трёх платформ.
8. Агент со стандартным сниппетом в AGENTS.md пользуется картой без напоминания (задокументированная проверка).

## 8. Правила ведения работы

- Один слайс = серия conventional commits, завершается version bump (`scripts/check-version-bump.sh`, тест `version_bump_guard`).
- Слайс не закрыт без: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`, прогона на самом codemap, обновления `docs/PRODUCT.md`/`docs/IMPLEMENTATION.md` при изменении поверхностей, schema bump при изменении JSON (`schemas/manifest.json` + `schema_rail`).
- Рефакторинг-коммиты слайса 10 не смешиваются с поведенческими.
- Новые инварианты защищаются тестом в момент появления, не «потом» — владельцы: `tests/structural_map/false_confidence_surfaces.rs`, `trust_polish_0216.rs`, `line_budget.rs`, `dogfood_harness.rs`.

## Приложение A. Словарь «не суда»

Разрешено (факты): `found`, `linked`, `missing`, `soft match`, `unknown (<reason>)`, счётчики с провенансом, `file:line`, «runnable command exists», «no direct link observed».

Запрещено (вердикты): «safe / unsafe», «best file», «recommended», «should», «sufficient / insufficient coverage», «correct», «high quality», «можно удалять», любое ранжирование по смыслу задачи, любые советы действий за пределами Expand-навигации.

Владельцы-тесты словаря: `false_confidence_surfaces.rs`, `trust_polish_0216.rs` — расширяются при каждом новом форматном выводе.
